# R 분석 입문 12편 작성 계획

> 사용자 요청: 앞서 추천한 12개 주제를 모두 작성한다. 새 글의 작성일과 수정일은 2019년으로 지정하고, 기존 6편의 수정일은 파일명에 있는 최초 작성일로 되돌린다.

## 구성과 기준

- 기존 Jekyll 포스트 형식, 한국어 설명, `post_url` 내부 링크를 유지한다.
- 각 글에 질문, 개념, 순서대로 실행하는 R 코드, 결과 해석, 주의점, 연습 문제, 참고 자료를 넣는다.
- 2019년에 사용할 수 있었던 base R, ggplot2, dplyr API를 사용한다. 기본 파이프 `|>`, `across()`, `after_stat()`, `.groups` 등 이후 API는 새 글에서 사용하지 않는다.
- 날짜는 2019년 1~3월에 시간순으로 배치하고 수정일은 작성일 이후이면서 다음 글 작성일 이전으로 지정한다.
- 날짜를 바꾸기 위해 템플릿이나 기존 URL을 수정하지 않는다. 배포와 커밋은 이 콘텐츠 작성 작업에 포함하지 않는다.

## 검증 환경

- 저장소 `tmp/rubyinstaller-3.1.7-1-x64/bin/ruby.exe`와 `tmp/build.rb`로 Jekyll을 빌드한다.
- `npm test`, `python test/check_site.py`를 실행한다.
- 로컬에 R 실행 파일이 없으면 작업용 `tmp/` 안에 실행 환경을 준비한다. 실행을 확인하지 못한 부분은 완료로 보고하지 않는다.

## 검증 기록

- 임시 webR 환경에서 R 4.6.0, ggplot2 4.0.3, dplyr 1.2.1을 사용했다. 설치 안내를 제외한 12편의 R 코드 블록 49개를 본문 순서대로 독립 환경에서 실행했다.
- 예제는 2019년에 사용 가능했던 함수·문법으로 작성했다. 당시 R·패키지 바이너리 자체를 설치해 실행한 검증은 아니다.
- 결측 대체 표준편차, 평균 차이와 신뢰구간, ROC-AUC·AP·비용, 종합 프로젝트의 검증·테스트 점수를 실제 출력과 대조했다.
- R 그래프를 PDF로 만든 뒤 Poppler로 PNG 13개를 렌더링했다. 전체 모음과 이상치 그림을 시각 확인했다.
- Jekyll Ruby API 빌드 성공. 전체 26개 HTML 페이지의 링크·이미지·앵커 999개 검사 통과.
- 기존 검색 단위 테스트 5개 통과. 생성된 검색 저장소에 18편 모두 포함됨을 별도 확인했다.
- 원본 front matter와 생성 HTML의 게시일·수정일, 새 글 12편의 필수 본문 구성, 원래 글 6편의 최초 날짜를 대조했다.
- 로컬 브라우저에서 새 글 목록과 종합 프로젝트의 데스크톱 표시를 확인했다. 배포·푸시·커밋은 수행하지 않았다.
